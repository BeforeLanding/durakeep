# 02 产品需求

- 版本：v1.0，2026-11-06
- 依据：原调研 `02-product-requirements.md`。本版把需求编号、按里程碑分档，并补齐验收条款。每条需求都能在 [08 测试计划](08-test-plan.md) 的验收矩阵中找到对应用例。

## 1. 产品目标

为**一个用户**持续保存有价值的资料，事后能找回依据、维护可编辑的个人记忆，并按明确的安排提醒。衡量价值的三句话是：

1. **找得到**：收藏过的东西，用自己的话能问出来。
2. **有依据**：回答里的事实能点回原文的具体版本和段落。
3. **不悄悄丢**：已接纳的输入、已创建的提醒，重启以后仍在；失败要看得见。

作为公开作品，额外要求：仓库能一条命令启动；不填 API key 时可以用演示模式（faux 模型 + 样例资料）走通主流程；`DECISIONS.md` 能讲清楚持久执行与幂等的设计。

## 2. 用户与使用环境

- 用户：作者本人。中文为主，夹杂英文技术资料。
- 环境：开发阶段在 Windows 11 本机；长期运行放在常开主机上。服务只绑定 `127.0.0.1`，外网访问不在 MVP 范围内。
- 模型：DeepSeek（`deepseek-flash` 为默认，`deepseek-v4-pro` 可选），允许把资料原文发给模型。这一点写在 README 的数据说明里。

## 3. 里程碑范围

| 档位 | 内容 |
|---|---|
| **P0 内核验证** | 不面向用户。验证 Pi 恢复、去重、共享文件和备份（见实施计划） |
| **P1 知识问答闭环** | 登录、对话、采集文本/Markdown/网页、版本、检索、带引用回答、资料页、任务状态、导出 |
| **P2 记忆与提醒** | 显式记忆、偏好 section、记忆候选、一次性提醒、站内通知、资料摘要、删除语义 |
| **P3 加固与展示** | 备份恢复演练、预算闸门、健康页、升级手册、演示模式与录屏；可选一个外部通知渠道 |

## 4. 功能需求

格式：编号 · 档位 · 需求，以及**验收**条款。“必须”表示达不到就不能进入下一档。

### 4.1 身份与访问（AUTH）

**FR-AUTH-01 · P1 · 单用户口令登录。** 首次启动时执行 `pnpm cli init`，设置口令（用 scrypt 哈希保存）。登录后发放 HttpOnly、`SameSite=Strict` 的会话 cookie，有效期 14 天。
- 验收：未登录访问任何 `/v1/*` 返回 401；连续 5 次口令错误后锁定 60 s；cookie 中不含可以解码出身份的明文。

**FR-AUTH-02 · P1 · 所有资源按 owner 隔离。** 每张业务表都有 `owner_id`，每次查询都必须带上它。工具参数里不出现 `owner_id`。
- 验收：用另一个 owner 的资源 ID 访问，返回 404，不是 403（不泄露资源是否存在）；工具参数里伪造 `owner_id` 无效。

**FR-AUTH-03 · P1 · 请求来源校验。** 修改类请求检查 `Origin` 必须与服务地址同源。服务默认只监听 `127.0.0.1`。
- 验收：带外部 Origin 的 POST 返回 403。

### 4.2 对话（CHAT）

**FR-CHAT-01 · P1 · 发送消息并持久接纳。** 客户端为每条消息生成 `client_request_id`（UUID）。服务端写入成功后才回复“已接纳”。
- 验收：同一个 ID 重发返回同一个 `submission_id`；同一个 ID 但内容不同返回 409；服务端在接纳后、响应前被杀掉，客户端重发后只出现一条消息（用例 R1）。

**FR-CHAT-02 · P1 · 流式查看并断线续看。** 对话页通过 SSE 接收状态；断线重连只补齐缺失的部分。
- 验收：刷新页面后能看到正在生成的回答继续推进；“已接纳”“生成中”“已完成”“失败”四种状态显示得清楚，“已提交”不会显示成“已完成”。

**FR-CHAT-03 · P1 · 忙碌时追加或纠偏。** 生成过程中可以发送新消息，默认排在当前 run 之后；勾选“插话”后作为 steer，在当前工具轮结束后生效。
- 验收：插话不会撤销已经开始的工具调用，界面上有相应说明。

**FR-CHAT-04 · P1 · 停止。** 点击“停止”会中止当前 run 并撤回排队中的输入。
- 验收：停止后会话进入空闲状态；已经写入的业务效果（例如已采集的资料）保留，并在界面上列出。

**FR-CHAT-05 · P1 · 失败可见、可继续。** run 因模型错误、轮次上限或崩溃上限而结束时，显示原因（中文）和可以采取的操作（“继续”或“重新发送”）。
- 验收：“继续”提交 `type: "continue"`；用户看不到堆栈；任何失败原因都不会让会话一直卡在“生成中”。

**FR-CHAT-06 · P1 · 多会话。** 可以新建、重命名会话，列表按最近活动时间排序。
- 验收：会话之间的上下文互不可见，但知识库和全局记忆是共享的。

### 4.3 知识库（KB）

**FR-KB-01 · P1 · 采集文本和 Markdown。** 可以在资料页粘贴、上传 `.md` / `.txt` 文件（≤2 MB），也可以在对话中说“把这段存下来”。
- 验收：内容哈希相同的资料重复导入，不会产生新版本，并提示“已存在”。

**FR-KB-02 · P1 · 采集公开网页。** 输入 URL 后在后台作业中抓取，保存原始 HTML 和抽取出的正文。
- 验收：只允许 http 和 https；拒绝 loopback、内网、链路本地和云元数据地址，重定向后的地址也要检查；响应 >5 MB、超过 20 s 或重定向超过 5 次时失败，并显示原因；失败后可以重试。

**FR-KB-03 · P1 · 不可变版本。** 同一个 URL 再次抓取到不同内容时，生成新版本，旧版本保留。
- 验收：历史回答中的引用仍然指向当时的版本。

**FR-KB-04 · P1 · 中文检索。** 支持词法检索，两字词也能搜到，可以按资料集合（标签）过滤。
- 验收：在评测集上，有答案的问题 Recall@10 ≥ 90%，两字词问题全部能召回。

**FR-KB-05 · P1 · 带引用的回答。** 回答中的事实性陈述附带引用 `[n]`，每个引用对应 `document_id`、`version_id`、`chunk_id` 和字符区间。服务端校验引用有效后再显示。
- 验收：引用定位有效率 100%（不存在或已删除的引用被拦下并标红）；资料不足的问题中，至少 9/10 会说明“现有资料不足”，而不是编造引用；资料里的结论、资料之间的冲突、助理自己的推断，在文字上要区分开。

**FR-KB-06 · P1 · 资料页。** 显示来源、版本列表、采集状态、标签，可以查看原文和抽取出的正文。
- 验收：原文和抽取正文有明确标记；采集失败的资料显示原因，并提供重试按钮。

**FR-KB-07 · P2 · 摘要。** 采集成功后在后台生成摘要，用户可以编辑；编辑后的摘要不会被自动覆盖。
- 验收：摘要失败不影响资料的检索状态；界面明确标出“模型摘要”。

**FR-KB-08 · P2 · 删除资料。** 分两种操作：“停止使用”（立即生效，可以撤销）和“彻底删除”（异步执行，删除原文、正文、片段和索引）。
- 验收：停止使用后，检索和引用校验都不会再返回这份资料；对话记录和压缩摘要中已经出现过的内容不在删除范围内，界面会明确说明（见 07 §6）。

### 4.4 长期记忆（MEM）

**FR-MEM-01 · P2 · 显式记住。** 用户说“记住……”时，模型调用 `memory_remember`，直接保存为已确认的记忆，并回执记忆的内容和作用范围。
- 验收：新会话中可以用到这条记忆；“假如我每天跑步”这类假设性的话不会被保存。

**FR-MEM-02 · P2 · 记忆页。** 区分“已确认”和“候选”，显示内容、类型、作用范围、来源和更新时间；可以修改、停用、删除。
- 验收：修改会生成新的 revision，旧 revision 可以查看；停用后立即不再注入，也不会被检索到。

**FR-MEM-03 · P2 · 冲突处理。** 同一个 key 写入新值时，旧记忆标记为 `superseded`。当次对话中的明确指令优先于长期偏好。
- 验收：互相矛盾的两条记忆不会同时出现在 section 或检索结果中。

**FR-MEM-04 · P2 · 候选提取。** 会话空闲 10 分钟后，在后台从新增的对话中提取候选记忆，用户在记忆页确认。
- 验收：已经删除或拒绝的记忆不会被再次提取出来（按 key 和值的哈希挡住）；涉及健康、财务、他人隐私的内容不会自动提取。

### 4.5 提醒（REM）

**FR-REM-01 · P2 · 创建一次性提醒。** 用户说“明天晚上八点提醒我看完这篇文章”时，模型调用 `reminder_create`，参数为本地时间和 IANA 时区。服务端换算成 UTC，并回显完整的日期、星期和时区。
- 验收：缺少日期或时间时模型会追问；时间已过去时拒绝创建；回显内容与实际触发时间一致。

**FR-REM-02 · P2 · 提醒列表与修改。** 可以查看、修改时间或内容、取消提醒。修改会让 revision 加一。
- 验收：修改后，旧 revision 到期时不会触发（用例 R4）。

**FR-REM-03 · P2 · 站内通知。** 提醒到期后生成站内通知，页面顶部显示未读数。通知分为“已生成”和“已读”两种状态。
- 验收：服务持续在线时，触发延迟 p95 ≤ 60 s；重启不会丢失提醒；在线时同一个提醒只通知一次。

**FR-REM-04 · P2 · 离线补发。** 服务停止期间到期的提醒，在重启后补发，并标记“迟到 N 分钟”。
- 验收：补发的计数与正常触发分开统计。

### 4.6 任务中心（TASK）

**FR-TASK-01 · P1 · 后台作业可见。** 采集、索引（P2 起还有摘要、提取）作业有 `queued`、`running`、`succeeded`、`failed`、`cancelled` 几种状态，可以重试或取消。
- 验收：关闭网页后作业继续执行；作业失败有原因；重试次数有上限（3 次，指数退避）。

**FR-TASK-02 · P1 · 运行异常可见。** Pi 的 `onReport` 报告（如 `task_faulted`、`storage_failed`）记入 `app_events`，在任务中心显示。
- 验收：故意制造一个崩溃循环，任务中心出现 `restart_limit` 记录，且不会无限重启。

### 4.7 运维与数据（OPS）

**FR-OPS-01 · P1 · 导出。** 可以下载一个 zip，包含资料原文、正文、记忆（JSON）和提醒（JSON）。
- 验收：导出文件不包含口令哈希、会话密钥或 API key。

**FR-OPS-02 · P3 · 备份与恢复。** 每天自动备份，保留 7 份，也可以手动触发。恢复由 CLI 执行，恢复后先暂停投递。
- 验收：在干净目录完成一次恢复演练，并记录恢复耗时和数据损失窗口。

**FR-OPS-03 · P3 · 用量与预算。** 显示本月 token 数和估算费用（按目录价）。到达 80% 时提醒，到达 100% 时暂停后台模型作业，交互对话仍可使用但会提示。
- 验收：预算闸门触发时，站内提醒照常投递，因为提醒的投递不需要调用模型。

**FR-OPS-04 · P3 · 健康页。** 显示进程运行时长、数据库大小、待执行作业数、失败作业数、待投递通知数、最近一次备份时间和 Pi 报告计数。

**FR-OPS-05 · P3 · 演示模式。** `pnpm demo` 使用 faux 模型和内置样例资料启动，不需要 key，可以走通“收藏 → 提问 → 引用 → 记住偏好 → 创建提醒”。

## 5. 非功能需求

| 编号 | 要求 |
|---|---|
| NFR-01 持久性 | 进程崩溃时不丢失已接纳的输入和已提交的业务写入；断电或宿主故障可能丢失最近的提交（SQLite NORMAL），README 写明这一点 |
| NFR-02 恢复 | 进程重启后 10 s 内恢复服务，未完成的 run 和作业自动继续，或明确标为失败 |
| NFR-03 时延 | 本机检索 p95 ≤ 300 ms（1 万个片段以内）；首个 token 的时间取决于模型，不作要求 |
| NFR-04 成本 | 正常使用下每月模型费用 ≤ 5 美元（按目录价估算，见 09 §6） |
| NFR-05 隐私 | 日志只记录 ID 和状态，不记录消息正文和资料正文；API key 只从环境变量读取 |
| NFR-06 可移植 | Windows 11 和 Linux 都能运行；不依赖原生编译模块 |
| NFR-07 可测 | 所有自动化测试使用 faux 模型和假时钟，零费用；付费评测每次运行都需要人工批准 |

## 6. 页面

| 页面 | 主要内容 |
|---|---|
| 登录 | 口令输入 |
| 对话 | 左侧会话列表；中间是消息流（引用以角标显示，悬停时显示片段）；底部输入框，有“插话”开关和“停止”按钮；运行状态条 |
| 资料 | 列表（标题、来源、状态、标签、版本数）；详情（版本、正文、摘要、原文链接、删除） |
| 记忆（P2） | 两个标签页：已确认 / 候选；编辑抽屉中显示 revision 历史 |
| 任务 | 作业、提醒、Pi 报告三个分区 |
| 设置（P3） | 模型选择、预算、备份、健康 |

交互约定：长操作先显示“已接纳”，再更新进度；失败消息包含原因和下一步操作；时间一律按用户时区显示，悬停时显示 UTC。

## 7. 自动行为边界

| 行为 | 是否自动 |
|---|---|
| 检索、读取资料、生成草稿 | 自动 |
| 采集用户在对话中给出的 URL 或文本 | 自动，回执中显示资料 ID |
| 用户明确说“记住”的偏好 | 自动保存为已确认，并回执 |
| 模型推断出的记忆 | 只作为候选，等用户确认 |
| 时间明确的一次性提醒 | 自动创建，并回显解析结果 |
| 删除资料或记忆、外发消息 | MVP 不提供给模型，只能在界面上操作 |

资料、网页和摘要中出现的“忽略指令”“发送密钥”等文字，一律只当作文本，不会触发任何工具授权。

## 8. 待定（不阻塞 P0/P1）

- （已定）项目名 `durakeep`，不使用 `pi-` 前缀，避免与 Earendil 官方包混淆。
- P3 是否接入外部通知渠道，以及接哪一个（国内可选飞书或企业微信机器人）。
- 常开主机的选择（本机常开或 Linux 小服务器）。
