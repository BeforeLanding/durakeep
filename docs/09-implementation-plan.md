# 09 实施计划

- 版本：v1.0，2026-11-06
- 工作量按一名熟悉 TypeScript 的开发者估算，单位是开发日。这是规划，不是承诺。每完成一个阶段（G0、G1）重新估算一次。

## 1. 总览

| 阶段 | 目标 | 估算 | 出口（Gate） |
|---|---|---|---|
| P0 | 验证内核，搭好骨架 | 3–4 天 | **G0**：08 §5 中的 K1–K7 全部通过，P0-REPORT 完成 |
| P1 | 知识问答闭环 | 6–8 天 | **G1**：检索评测达标；R1、R6、R7、R9、R10、R13 和 S1–S12 通过；一次付费回答评测（需批准）达标 |
| P2 | 记忆与提醒 | 4–5 天 | **G2**：FR-MEM、FR-REM 验收通过；R4、R5、R14 通过 |
| P3 | 加固与展示 | 3–4 天 | **G3**：恢复演练完成；演示模式和录屏完成；README 与 DECISIONS 定稿；公开仓库 |
| 合计 | | **16–21 天** | |

比原调研多出约 2 天，原因是加入了演示模式、CI 双平台和展示材料（作品需要）。

## 2. 任务卡片

每个任务的格式：**ID · 名称**（估算）· 依赖 · 产出 · 完成标准（DoD）。DoD 中的测试必须实际运行通过，不能只写出来。

### P0 内核验证

**T-00 · 仓库骨架**（0.5）· 无依赖
- 产出：pnpm workspace；tsconfig 开启 `erasableSyntaxOnly`（Node 直接运行 TS，不需要构建）；vitest；eslint + `dependency-cruiser` 规则（只有 `runtime-pi` 可以 import `@earendil-works/*`；业务包不能依赖 `runtime-pi`）；`.nvmrc`（24）；`engines >=22.19.0`；CI 工作流（两个系统 × 两个 Node 版本）；`AGENTS.md`、`CLAUDE.md`。

**T-02 · 共享数据库验证（ADR-02）**（0.5）· T-01

**T-03 · section 与 write 语义验证（ADR-05）**（0.5）· T-01

- DoD：K4 通过；R2 重复 20 次通过；在事务回调中误用外层 db 的情况，有单元测试证明会被检测到（抛错，而不是挂死）。

## 4. 规划与执行的交接方式

采用规划者 / 执行者分工，两者通过仓库内的文件交接，不靠手工复制提示词：

- `docs/TASKS.md`：从本文复制任务卡片，状态有 `todo`、`doing`、`review`、`done`。执行者每次只领取一张卡。
- `docs/PROGRESS.md`：执行者在每张卡完成时追加一条记录，包括改了什么、运行了哪些测试和结果、遇到的意外。
- 规划者只阅读 PROGRESS 和 diff，然后更新 TASKS 或 ADR。
- 遇到以下情况，执行者必须停下来交回：任何付费调用；需要修改 ADR；任务超出估算的 2 倍；需要用户提供数据。

## 5. 风险

| 风险 | 可能性 | 影响 | 应对 |
|---|---|---|---|
| ADR-02 共享数据库在 Node 下不稳定 | 中 | 中 | T-02 中尽早验证；回退到双文件，备份时停服 |
| 读不到 run 锚点 | 中 | 中 | 05 §5.2 的备选方案（`app.run_meta` Document） |
| DeepSeek 的工具调用或引用格式遵从度差 | 中 | 高 | T-19 付费评测时尽早发现；可以改用 `deepseek-v4-pro`，或改成在回答之后用结构化工具提交引用 |
| 中文网页抽取质量差 | 中 | 中 | T-13 做 10 个页面的抽样；可以换 jsdom，或者让用户粘贴正文 |
| 只用词法检索，召回率达不到 90% | 中 | 中 | ADR-06 的触发条件；暂停并和用户商量 |
| pi-durable 在开发期间发布不兼容的新版本 | 高 | 低 | 版本锁死；MVP 期间不升级 |
| 范围蔓延（多渠道、多 agent、embedding） | 中 | 高 | PRD 第 3 节的“以后”和“不做”清单；新增功能必须先更新 PRD |

## 6. 成本估算（按目录价，未核实官方价格）

假设：每天 30 次对话请求；平均每次输入 6,000 tokens（其中约 4,000 tokens 是可以命中缓存的稳定前缀）、输出 800 tokens；每次 run 平均 1.5 次模型请求（包括工具轮）。

| 项目 | 月用量 | `deepseek-flash` 费用 |
|---|---|---|
| 输入，缓存未命中部分（2,000 × 1.5 × 30 × 30） | 2.7 M | 0.81 美元 |
| 输入，缓存命中部分（4,000 × 1.5 × 30 × 30） | 5.4 M | 0.03 美元 |
| 输出（800 × 1.5 × 30 × 30） | 1.08 M | 1.30 美元 |
| 摘要与提取（每月 100 篇资料 × 8k 输入 + 300 输出；提取 60 次 × 4k） | 约 1.1 M 输入，约 0.05 M 输出 | 0.39 美元 |
| **合计** | | **约 2.5 美元 / 月** |

改用 `deepseek-v4-pro` 时，各项单价是 flash 的 3.3–4.4 倍，合计约 10 美元 / 月。预算闸门的默认值为每月 5 美元。表中没有计入失败重试、压缩和评测运行；一次 50 题的回答评测约为 0.3–1 美元（flash），以 dry-run 的预估为准。
