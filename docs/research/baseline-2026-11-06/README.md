# 基于 pi-durable 的个人知识与日常助理

调研日期：2026 年 11 月 6 日，Asia/Shanghai。面向：准备开发个人 agent 的产品与工程负责人。用户已确认重点为知识管理与日常助理。

## 结论与建议

**建议采用 pi-durable 作为 MVP 的可恢复执行内核，先通过故障恢复验证，再建设个人知识与记忆功能。** 它适合需要后台运行、接收后续指令、跨进程重启继续工作的个人助理；但不是开箱即用的个人助理产品。知识检索、长期记忆、日程语义、身份认证、外部操作授权与通知去重仍需自行建设。

建议的起点是 TypeScript、Node.js、单进程服务、SQLite 和 Web 界面。先服务一个用户，支持文本、Markdown、网页收藏、带来源问答、明确偏好的记忆和一次性提醒；确认使用价值后再接入 PDF、日历、邮件、即时通信和更多模型。

这项建议是基于官方文档、规范、发布记录及源码样例的工程判断，**不是性能测试或生产可用性认证**。尚未安装运行 agent、调用付费模型、测试故障恢复或部署服务。

## 已核实的几个关键事实

- 调研时 npm 的 latest 为 **1.5.0**，发布于 2026-11-02；包声明 Node.js **≥22.19.0**，MIT 许可。版本号与发布元数据已保存在 `sources/`，发布包的 SHA-512 已与 registry 的 integrity 校验一致。[npm 版本元数据](https://registry.npmjs.org/@earendil-works%2fpi-durable/1.5.0)
- 发布包仍标记 Experimental。1.5.0 对工具 schema、存储协议和观察接口等进行了破坏性修改，应固定版本并保留升级测试。[发布记录](https://github.com/earendil-works/pi/blob/2a32a605a9f18a5f0191f65358a2e764b2f69fc7/packages/durable/CHANGELOG.md)
- 框架支持持久化会话、任务检查点、输入去重、工具恢复、上下文压缩和持久化休眠；外部效果是否发生一次，需要业务和外部系统共同保证。[官方 README](https://github.com/earendil-works/pi/blob/2a32a605a9f18a5f0191f65358a2e764b2f69fc7/packages/durable/README.md)
- 默认 SQLite 使用 WAL 与 `synchronous=NORMAL`，进程崩溃与断电故障的保证不同；流式中间输出默认可延迟约一秒落盘，不能宣传为“每个显示出的字都不会丢”。[发布包 README](sources/published-1.5.0/package/README.md)

## 本方案的默认假设

单人使用、中文为主、模型可以使用云 API、先采用 Web 入口；开发可在当前 Windows 环境进行，长期运行优先选择常开主机或 Linux 小型服务器。服务休眠或关机期间无法准时通知，恢复后按补发策略处理。

默认假设可以替换，不代表用户已经选择云服务、模型供应商、部署地区或授权导入私人资料。本轮没有读取工作区现有知识库、密钥文件或个人聊天记录。

## 第一个里程碑

先完成一条可验证链路：提交带固定请求 ID 的任务 → 落盘 → 中途杀进程 → 重启 → 读取原任务结果；然后验证一次性提醒在重启后仍存在，并在故障窗口中不会未经核对重复执行外部操作。通过后再接入真实个人资料。
