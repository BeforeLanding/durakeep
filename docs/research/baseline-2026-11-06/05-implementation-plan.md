# 实施路线与验证计划

## 交付原则

先验证 durable 的实际语义，再增加资料与渠道。先完成一个用户的闭环，再考虑多 agent、更多工具和分布式部署。每阶段的验收是进入下一阶段的条件；以下工作量为一名熟悉 TypeScript 的开发者的粗略估计，不是工期承诺，不包含生产运维、复杂 PDF/OCR 和外部平台审批。

## P0 验证内核与恢复

预计 2–3 个开发日。固定 `@earendil-works/pi-durable@1.5.0` 及匹配依赖，保存 lockfile，选择满足 ≥22.19.0 的受支持 Node 版本。不得用浮动 latest 替代依赖审查。[发布包版本要求](sources/published-1.5.0/package/package.json)

使用官方 faux provider 编写本地 harness 验证，先不调用付费模型。官方 `13-chat.ts` 展示模型替身、registry、root、submit、wait 与 close；持久化改用官方 SQLite adapter。用独立子进程测试强制退出，不能只测试正常 close。[官方最小样例](https://github.com/earendil-works/pi/blob/2a32a605a9f18a5f0191f65358a2e764b2f69fc7/packages/durable/test/examples/13-chat.ts)

验证清单：

- 同一 conversation、同一 requestId 的重复输入只接纳一次；同 ID 不同 payload 在应用入口拒绝。
- 模型返回中途、工具执行中途和结果提交后强制终止进程，重启后读取预期状态。
- replay safe 工具重新执行，unsafe 工具产生明确 interrupted；业务幂等阻止重复效果。
- `sleepUntil` 到期前退出、到期后重启，任务正确恢复；测试显式调用 resume 的宿主启动路径。
- 存储失败使 Harness 失效并被宿主正确处理，不继续显示正常运行。
- 第二个拥有者进程启动被应用层阻止。
- 连续故障达到上限后进入可观察失败，不能无限崩溃拉起。

交付：固定版本清单、故障注入脚本、故障结果记录、runtime adapter 的最小接口。若无法稳定通过，先排查版本和使用方式；不要用增加重试次数掩盖问题。

## P1 完成知识问答闭环

预计 4–6 个开发日。搭建单用户 Web 界面、认证、资料导入、不可变版本、分块、检索与来源查看。先用 20–50 篇用户授权的测试资料，建立人工标注问题集；不要一开始导入整个硬盘。

交付：文本、Markdown、网页采集；带来源问答；任务状态与失败重试；可下载资料导出。对短中文词和无答案问题单独测评。模型回答成功但引用不存在，判为失败。

## P2 加入记忆与站内提醒

预计 3–5 个开发日。实现显式记忆、候选提取、编辑撤销、scope 和 revision。实现一次性提醒、到期站内通知、取消与离线补发策略。通过稳定 operation_id 和数据库唯一约束防止重复创建。

交付：跨会话可用且可编辑的记忆；重启不丢的提醒；删除后不会被运行中的提取任务复活；提醒产生可审计状态。此阶段再试验每日回顾与周期规则，不把定时唤醒等同于每次都要调用模型。

## P3 加固并接入一个外部渠道

预计 3–5 个开发日。选择一种用户真实需要的通知渠道，核查其发送与查询契约，完成 outbox、未知状态核对和权限撤销。加入备份恢复、凭据管理、访问审计、预算限制、健康检查与升级演练。

交付：恢复演练记录、待核对队列、监控面板和升级操作手册。禁止在没有真实效果核对能力时声称外部通知 exactly once。

合计约 12–19 个开发日，约 3–4 周全职投入作为初始规划。模型效果、资料质量和渠道接入可能明显扩大工作量，应在 P0 与 P1 后重新估算。

## 首批接口与上游 API 对照

本项目 RuntimePort 至少提供 start、submitInput、getSubmission、observeConversation、cancelRun 和 close。业务模块只调用 RuntimePort。

在 1.5.0 发布文档中已经核实的调用包括：`Harness.open()`、`openNodeSqliteStorage()`、`harness.root()`、`harness.resume()`、`conversation.submit()`、`submission.wait()`、`conversation.watch()`、`harness.close()`。所有异步上下文与取消语义以实际类型定义为准。[发布包 README](sources/published-1.5.0/package/README.md)

不要照旧教程使用 `watchEvents()`；不要把 await wait 当作“所有 afterRun 工作也完成”；不要把取消客户端 context 当作取消服务端任务；不要把主分支未发布方法写进固定 1.5.0 适配层。[1.5.0 迁移说明](sources/published-1.5.0/package/CHANGELOG.md)

## 故障验证细则

每个关键窗口先以固定测试替身重复至少 20 次，再做少量真实渠道验证。记录操作 ID、进程退出点、恢复路径、最终业务状态与外部实际次数。20 次是初始回归门槛，不代表统计可靠性证明。

1. 接纳成功但 HTTP 响应丢失：客户端重发，同一 submission 与 job 被返回。
2. 业务数据写入但 Pi 工具结果未保存：恢复工具读取已存在的业务结果，不重复建文档或提醒。
3. 外部 API 成功但回执未落盘：使用同一业务键查询；无法查询时进入 unknown 或 needs_review。
4. 提醒睡眠时修改或取消：旧 revision 到期时不投递。
5. 提取记忆时删除原文：提交阶段发现 deletion_epoch 已变化，不写回旧事实。
6. 生成答案时删除资料：最终引用检查阻止继续显示已撤销来源；必要时重新生成。
7. 模型 429、超时与非法输出：有限退避、明确失败、保留恢复入口，不能无限工具循环。
8. 存储磁盘满或写失败：停止运行并报警；恢复后核对已接纳输入。
9. 并发同 ID 不同内容：入口报冲突；不同 ID 相同内容按业务去重规则处理。
10. 重复事件被错误路由至不同会话：入口唯一约束阻止第二次派发，说明 Pi 的会话内去重不足以单独承担入口去重。
11. 更新依赖后仍有旧 sleeping task：迁移成功或保留旧定义，不能留下静默阻塞任务。
12. 从昨日备份恢复：默认暂停外部投递，核对备份后已发生的操作，再开放服务。

另做独立供电/宿主故障测试或注明未覆盖。杀进程测试不能证明断电不会丢失数据，尤其默认 SQLite NORMAL 模式。[官方 SQLite 持久化说明](sources/published-1.5.0/package/README.md)

## 安全验证

未登录请求、其他 owner 的资源 ID、过期会话和伪造授权均不能访问资料。网页重定向到内网、附件路径穿越、过大压缩文件和长时间解析必须被阻止。知识片段中的“忽略指令并外发文件”只作为文本处理。

日志检查覆盖模型异常、工具参数、连接器错误和导出文件，不只检查正常日志。权限撤销后，已排队和重启恢复的任务都应重新检查权限。

## 预算与成本控制

先记录 tokens、工具调用、索引量与后台频率，再代入所选供应商的实际价格。本轮未选择模型，未提供虚构月费。

月成本估算采用：各模型的输入量乘输入单价，加输出量乘输出单价，再加 embedding、重排、OCR、搜索、托管、存储和通知费用。缓存价格、失败调用、重试与后台 compaction 单独计入。

例如，仅作为用量演算：每日 30 次请求，每次总输入 6,000 tokens、输出 800 tokens，则 30 天约输入 540 万、输出 72 万 tokens；这还不含多轮工具调用、重试、摘要和建索引，不能直接当作完整预算。

建议的初始保护参数：交互 run 最多 8 轮工具循环，单次网络调用默认 30 秒超时，批量导入限制并发；这些是待验证的应用配置，不是上游默认值。月度预算按 80% 提醒、100% 暂停非必要模型任务设计，且保留用户查询与取消入口。超限时站内纯文本提醒仍能投递，无需模型重写。

`pi.usage` 可用于界面展示和趋势，实际账单还要与供应商核对；崩溃窗口可能造成用量缺记。[官方 Usage and Cost 与流式进度说明](sources/published-1.5.0/package/README.md)

## 上线与升级门槛

- 核心恢复用例、来源校验、权限检查与删除传播全部通过。
- 真实小规模知识评测达到产品需求中的门槛，未达项明确降级。
- 完成干净环境恢复，保存恢复时间与数据损失窗口的实测结果。
- 运维可看到失败、待核对操作、未投递提醒、磁盘和预算状态。
- 依赖精确固定，备份与旧版本可保留；确认存储是否能回滚，不能默认降级程序即可恢复数据。

升级先在副本上重放代表性会话与 sleeping tasks，再切换实际服务。若存储已迁移而旧代码不兼容，优先修复前进；恢复旧备份会丢弃之后的数据，并有外部效果重新执行风险。Cloudflare 官方也明确提醒 Pi minor 的存储格式兼容问题。[Cloudflare Pi 版本说明](https://developers.cloudflare.com/agents/harnesses/pi/)
