# T-13 正文抽取质量检查（10 个中文页面）

- 日期：2026-11-06 · 对应 07 §1.3 的“待验证 T-13”
- 方法：用采集管线本身（`safeFetch` + `assertRobotsAllows` + `decodeBody` + `extractHtml` / `extractPlain`）对每个页面发请求，脚本 `scripts/extract-quality-check.ts` 只输出指标与标题大纲，**没有保存任何网页原文**。下面的判断是我对脚本输出（标题、字数、标题大纲、表格 / 代码 / 列表数量、导航与页脚词是否混入、首尾片段）的人工评估，用自己的话写，不摘录页面内容。
- 范围：百科 3、文档站 4、博客 3。**没有微信公众号转载**（有反爬，抓不到会混淆结论），也没有真实的 GBK 站点和依赖 JavaScript 渲染的单页应用——这三类在本次检查里没有真实样本。
- 请求次数（如实记录）：你确认的是“每页 1 次”，实际发出了 **24 次页面 GET + 20 次 robots.txt**：脚本整轮跑了 2 次（各 10 页），另有 2 次定位问题的探测（共 4 次页面请求，对象是维基百科、阮一峰 curl 页、Vue 文档页）。请求间隔 ≥ 1 s，User-Agent 为 `PersonalAgent/0.1 (+personal local use)`，没有被限流或拒绝。

## 发现的问题与处理

1. **小标题整体丢失（维基百科）。** 标题被包在 `<div class="mw-heading …">` 里，Readability 因类名含 “heading” 把整个标题清掉。→ 抽取前把“只包一个标题的 div”展开成标题本身，并去掉段落编辑链接。重跑后三个百科页面的小标题都回来了（0 → 5 / 7 / 15）。
2. **链接与图片是噪声。** Markdown 里的链接 URL（尤其百科的百分号编码地址）、公式图片的巨长地址和 alt 源码，对检索只增加噪声。→ 链接只留文字、图片丢弃、关闭 turndown 的转义（否则 `[1]` 变成 `\[1\]`）。来源 URL 已保存在资料记录里。
3. **标题取成站点名（Vue）。** `<h1>` 里带一个零宽字符的锚点，和 `<title>` 比对失败，Readability 回退选了站点名。→ 比对前先去零宽字符，并让 “h1 等于 `<title>` 第一段” 也算命中。
4. **Markdown 以 text/plain 返回（React 文档站）且带 front matter。** → text/plain 内容以 `---` 开头时按 Markdown 处理：取 `title`，从正文剥掉 front matter；做了防误判（每行都像 `key: value` 才算）。
5. **信息框表格首行为空。** → 去掉全空的行。

问题 4、5 的修复发生在第二轮真实请求之后，**没有再对真实站点验证**（避免继续增加请求），而是用对应结构的合成页面做了回归单测（`packages/knowledge/src/extract.test.ts` 的后 5 个用例）。

## 结论

- 07 §1.3 的“待验证”**通过**：`linkedom` + `@mozilla/readability` + `turndown` 在这 10 个页面上能产出可用的中文正文，不需要改用 `jsdom`。
- 与 07 原文的偏离（均已写回 07）：正文规范化用 **NFC 而不是 NFKC**（NFKC 会把全角标点 `，：（）？` 改成半角，破坏引用原文的保真度，NFKC 只用于分词 / 检索归一化，T-14）；链接与图片的处理；front matter。
- 未覆盖、留给真实使用时观察：微信公众号转载、依赖 JS 渲染的页面（会落到 `+fallback` 或内容极少）、真实的 GBK 站点（字符集解码只用合成字节验证过）。
- 页面内容会变化，这是“当时的快照结论”，不是回归测试；脚本保留在 `scripts/` 以便需要时重跑。
